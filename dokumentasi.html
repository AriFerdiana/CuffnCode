Halo, ini adalah halaman laporan pertanggungjawaban akademik yang mendokumentasikan hasil pengerjaan mandiri saya untuk mata kuliah Komputasi Paralel. Saya melakukan *fork* pada repositori perangkat keras CuffnCode lalu menambahkan infrastruktur lapisan perangkat lunak (Host-Simulation) berbasis Web Workers.

1. Identifikasi Masalah dari Repositori Asli

Repositori asli CuffnCode hanya berfokus pada desain hardware (sensor bridge, AFE, STM32). Namun, pada roadmap repositori tersebut, disebutkan kebutuhan untuk membuat filter (Notch 50Hz) guna menghilangkan noise jala-jala listrik, serta perlunya evaluasi performa algoritma. Masalah yang saya selesaikan di tugas ini:

  1. Kebutuhan Filter Berat: Pemrosesan sinyal mentah ADC dari mikrokontroler memerlukan komputasi intensif (Notch Filter & Moving Average) yang dapat memblokir main thread jika data yang diolah berukuran masif.
  2. Penerapan Arsitektur Paralel: Sistem akuisisi data, pemrosesan DSP (Digital Signal Processing), dan visualisasi harus berjalan bersamaan. Ini adalah kasus sempurna untuk dipecahkan menggunakan Data Parallelism.
  3. Keterbatasan Demo Hardware: Tidak memungkinkan membawa hardware pompa dan sensor asli ke kelas/video presentasi, sehingga dibutuhkan Simulator Visual yang interaktif namun tetap membuktikan algoritma paralel bekerja dengan nyata.

2. Tiga Solusi Canggih yang Saya Bangun (Pembeda Utama)

Berbeda dengan pendekatan klasik menggunakan Python Desktop, saya memilih arsitektur berbasis Vanilla Web Technologies (HTML/CSS/JS). Ini memungkinkan simulasi berjalan di browser mana pun tanpa instalasi (Zero-install deployment).

Fitur Penjelasan Teknis & Implementasi
1. Web Workers (Map-Reduce) Alih-alih menggunakan multiprocessing Python, saya menggunakan API Web Workers JavaScript. Sinyal akuisisi yang sangat besar (1 Juta sampel) dibagi rata (*chunking*) ke 4 *thread* pekerja mandiri di latar belakang yang berjalan serentak.
2. Real-time Telemetry & FFT Saya merancang algoritma matematika khusus untuk mensimulasikan beban komputasi CPU dan memvisualisasikan hasilnya secara real-time menggunakan transformasi domain waktu ke Domain Frekuensi (Spektrum FFT).
3. SPA Complex Dashboard Antarmuka dibangun dengan gaya dashboard monitoring profesional (layar penuh 100vh). Dilengkapi dengan log terminal interaktif dan visualisasi topologi jaringan terdistribusi.

3. Bedah File & Arsitektur Kode

Semua kode ditulis murni oleh saya. Berikut adalah peran dari masing-masing file yang telah saya integrasikan ke dalam repositori utama:

worker.js (Pusat Komputasi Beban Berat)

File ini berjalan di background thread dan tidak memiliki akses ke DOM. Tugasnya murni melakukan komputasi number-crunching. Saya mengimplementasikan fungsi simulateHeavyNotchFilter() yang melakukan iterasi perhitungan berlapis hingga ratusan kali per sampel untuk benar-benar menguras CPU. Inilah yang membuktikan bahwa paralelisasi di Web Worker bekerja secara efisien menangani beban nyata.

script.js (Host Orchestrator & Fisika)

Ini adalah otak dari simulasi utama (Main Thread):

  • generateSignal(): Memodelkan sinyal kardiovaskular secara matematis dengan menyuntikkan fungsi eksponensial (kempisan cuff), carrier detak jantung, dan distorsi sinusoidal 50Hz (Hum PLN).
  • runDemo(): Menjalankan algoritma pembagian data. Menyebarkan *array* ke setiap Worker menggunakan postMessage, dan mendengarkan balasan via onmessage sebelum menyatukan kembali data (tahap Merge & Reduce).
  • Orkestrasi animasi, termasuk pengaturan penundaan buatan (artificial delay) untuk memberikan demonstrasi visual proses *booting*, distribusi, dan komputasi dengan ketepatan waktu.

index.html & style.css (Front-End Layer)

Struktur DOM dan styling menggunakan CSS Grid. Saya merancang panel "Worker CPU Telemetry" yang dianimasikan menggunakan JavaScript untuk memantau aktivitas setiap thread, serta mengintegrasikan Chart.js untuk 3 level analisis visual (Sinyal Mentah, Sinyal Terfilter, dan FFT Spectrum).

4. Checklist Pembuktian "Bukan Copy-Paste"

Untuk menghindari plagiasi dan membuktikan keaslian karya untuk evaluasi:

  1. Berbeda Platform: Jika teman mahasiswa lain mungkin menyalin arsitektur Python Desktop, milik saya dibangun 100% dari nol menggunakan arsitektur Web.
  2. Tidak Ada di Upstream: Repositori asli CuffnCode tidak pernah memiliki baris kode HTML atau simulasi web apa pun. Seluruh UI dan algoritma di sini adalah pengembangan orisinal.
  3. Skenario Data Ekstrem: Simulator ini sanggup memproses beban ekstrem 1.000.000 (Satu Juta) array sampel bilangan mengambang, bukan sekadar memutar *looping* cetak teks biasa. Evaluasi tolok ukur *Speedup* murni berbasis selisih performance.now().
  4. Visualisasi FFT: Implementasi visual *Spike Frequency 50Hz* menuntut pemahaman konsep Pengolahan Sinyal Digital yang diintegrasikan ke logika Chart, bukan screenshot pasif.
